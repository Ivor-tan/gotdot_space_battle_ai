# 舰队编队与羁绊

> 本文只定义局内舰队的格位、连通、羁绊和数据规则。舰船永久解锁见 `meta_progression.md`，数值硬上限见 `combat_rules.md`。舰船没有生命、护甲或修复：任何“保护”效果只能授予护盾、控制、位移或一次性免伤。

## 1. 编队目标与硬规则

- 玩家操控的是虚拟舰队锚点的移动；所有舰船保持相对格位、自动攻击和施放自身效果，没有固定旗舰或不可交换的核心舰。
- 正式版满编为 **19 艘**：中心格 1、第一环 6 格、第二环 12 格。MVP 可只开放第一环（7 艘）。
- 所有已部署舰船均可与任意合法格位交换，包括中心格；某艘舰被击毁时立即退出战斗并释放其格位。
- 舰队中最后一艘舰船被击毁时，本局结束；只要仍有一艘已部署舰船，舰队锚点和战斗继续存在。
- 外环格位只有与虚拟锚点存在连续占格路径时可部署；安全窗口与暂停菜单均可编辑舰队。
- 同时激活羁绊上限为 6 条，标签协同上限为 4 条；超过上限的候选显示原因但不生效。

## 2. 六边形格位数据

格位使用轴坐标 `q,r`；`(0,0)` 是可部署、可交换的中心格，虚拟舰队锚点位于其几何中心但不属于任何舰船。编队“前方”取锚点当前移动朝向，坐标只定义相邻关系，视觉层随朝向旋转。

| 环 / 职责带 | 坐标 | 数量 | 格位效果 | 主要职责 |
| --- | --- | ---: | --- | --- |
| 中心 `CENTER` | `(0,0)` | 1 | 任意舰船可部署；与第一环六格相邻。 | 控制、守卫、弹性位。 |
| 第一环前侧 `FRONT_1` | `(0,-1)`、`(1,-1)` | 2 | 敌方目标优先度 +25%；近距武器伤害 +15%。 | 守卫、突击。 |
| 第一环中侧 `MID_1` | `(1,0)`、`(-1,0)` | 2 | 相邻支援/控制效果距离 +1 格。 | 支援、控制。 |
| 第一环后侧 `REAR_1` | `(0,1)`、`(-1,1)` | 2 | 攻击范围 +10%，仍受 900 px 硬上限。 | 炮击、母舰。 |
| 第二环前侧 `FRONT_2` | `(0,-2)`、`(1,-2)`、`(2,-2)`、`(-1,-1)` | 4 | 敌方目标优先度 +15%；不再额外提高近距武器伤害。 | 守卫、突击。 |
| 第二环中侧 `MID_2` | `(2,-1)`、`(2,0)`、`(-2,0)`、`(-2,1)` | 4 | 可接收相邻链路，但不延长支援距离。 | 控制、支援、弹性位。 |
| 第二环后侧 `REAR_2` | `(1,1)`、`(0,2)`、`(-1,2)`、`(-2,2)` | 4 | 攻击范围 +10%；被侧翼敌锁定的准备时间 -0.25 秒。 | 炮击、母舰、支援。 |

> 第二环坐标在实现前必须以一份唯一 `FormationSlotData` 表校验，不能从上表手写推导。每个槽位只能属于一个职责带；若视觉朝向转换，职责带随舰队锚点朝向转换而非改写坐标。

### 格位与连通

| 规则 | 判定 | 结果 |
| --- | --- | --- |
| 相邻 | 六个轴向方向之一：`(+1,0)`、`(+1,-1)`、`(0,-1)`、`(-1,0)`、`(-1,+1)`、`(0,+1)`。 | 可建立相邻链路或满足羁绊边。 |
| 连通 | 第一环已部署舰直接连接虚拟锚点；第二环舰沿相邻占格可到达第一环。 | 不连通舰不得确认部署。 |
| 外环许可 | 第二环格至少有 1 个已占用的第一环相邻格。 | 防止跳过内环直放远程火力。 |
| 击毁释放 | 舰船被击毁时立刻清空 `ActiveOccupantId`。 | 原格位可由之后获得的新舰船部署；相关链路与羁绊立即重算。 |
| 格位收益 | 舰船已部署且格位有效。 | 舰船被击毁或脱格后立即失效。 |

## 3. 编队编辑流程

### 安全编辑

招募新舰、精英/Boss 奖励结算、遭遇完成、进入下一波前允许免费编辑。玩家拖拽舰船到空格或选择两舰交换；确认前显示所有变化预览，确认后同一帧重算格位、链路、标签协同与羁绊。

由升级、信标或遭遇奖励获得一艘新舰时，系统以“待部署舰”打开舰船编辑页面：该舰显示在左侧待部署区，确认前不提供格位收益、链路或羁绊。玩家可将其拖入合法空格，也可拖到一艘**同名、同星、未达 4 星**的已部署舰上请求融合。部署时校验目标格；融合时校验舰船 ID、星级与上限。两种确认均在同一帧原子完成并只重算一次阵列。取消则保留待部署奖励并返回来源选择页，不消耗额外资源。

### 同名舰融合与继承

| 项目 | 规则 |
| --- | --- |
| 合法条件 | 待部署舰与目标舰 `ShipId`、`StarLevel` 相同，目标舰低于 4 星；无需额外空格，满编时也可融合。 |
| 结果 | 消耗两艘舰，保留目标舰原格位与 `ActiveOccupantId`，`StarLevel + 1`；待部署舰从未入阵，因此不产生短暂羁绊或双重计数。 |
| 本局单舰改造 | 仅继承目标舰已经获得的改造，待部署舰不携带卡牌；同类改造层数不翻倍。舰种共享路线仍按原有已选层数结算。 |
| 护盾与临时状态 | 先清除两舰护盾、无敌、叠层、冷却与一次性触发状态，再按升星后的基础值重建，避免利用融合刷新防御窗口。 |
| 4 星重复 | 4 星不能融合；同名奖励在奖励页直接转为 `RUN_EXP`，不占待部署栏。 |

## 4. 系统数据模型

### 编队槽位 `FormationSlotData`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `SlotId` | `StringName` | 例如 `SLT_R1_FRONT_001`；删除后不复用。 |
| `AxialCoordinate` | `Vector2I` | `q,r` 轴坐标。 |
| `RingIndex` | `int` | `0` 中心、`1` 第一环、`2` 第二环。 |
| `PositionBand` | enum | `Core`、`Front`、`Middle`、`Rear`。 |
| `UnlockRuleId` | `StringName` | 环、事件或卡牌开放条件。 |
| `AdjacentSlotIds` | `Array<StringName>` | 预计算六邻居，运行时不全表搜索。 |
| `ActiveOccupantId` | `int` | 本局舰船实例 ID；舰船被击毁后立即清空。 |

### 本局舰船状态 `ShipRuntimeState`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `InstanceId` | `int` | 本局唯一实例 ID；融合后沿用目标舰 ID，便于 HUD、格位和羁绊引用保持稳定。 |
| `ShipId` | `StringName` | 舰船稳定定义 ID；融合必须完全相同，不能只比较职能标签。 |
| `StarLevel` | `int` | 1～4；新招募舰为 1，融合成功后 +1，结算时丢弃。 |
| `PendingSourceId` | `StringName` | 仅待部署舰填写，记录升级、信标或遭遇来源，取消时返回对应奖励页。 |
| `SingleShipUpgradeIds` | `Set<StringName>` | 已应用于该实例的局内单舰改造；融合只保留目标舰集合。 |
| `TemporaryCombatState` | runtime struct | 护盾、无敌、叠层、冷却与一次性触发；融合时清除并重建。 |

### 羁绊定义 `BondDefinition`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `BondId` | `StringName` | `BND_<结构>_<序号>`；结构为 `PAI` 二舰、`TRI` 三舰、`TAG` 标签、`POS` 格位。 |
| `NameKey` / `DescriptionKey` | `StringName` | 本地化文本，不将显示名写入 ID。 |
| `MemberShipIds` | `Array<StringName>` | 具名成员的稳定舰船 ID，顺序不影响判定。 |
| `RequiredEdges` | `Array<BondEdgeRule>` | 必须相邻、相隔一格、前后关系等边条件。 |
| `RequiredBands` | `Dictionary<ShipId, PositionBand>` | 仅在必须限制格位时填写。 |
| `RequiredAlive` | `bool` | 当前具名羁绊固定为 `true`。 |
| `Priority` | `int` | 三舰 200、二舰 100、标签 50；只用于超上限取舍。 |
| `EffectId` | `StringName` | 指向效果执行器；效果配置不内嵌在条件表。 |
| `CooldownSeconds` | `float` | 0 表示常驻；触发型效果必须填写。 |
| `MaxStacks` | `int` | 默认 1；不得超过 3。 |

### 运行时状态 `BondRuntimeState`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `BondId` | `StringName` | 对应定义。 |
| `State` | enum | `Active`、`MissingMember`、`InvalidPosition`、`Suppressed`、`Capped`。 |
| `ActiveMemberIds` | `Array<int>` | 当前参与的舰船实例。 |
| `RemainingCooldown` | `float` | 触发型羁绊的剩余冷却。 |
| `StackCount` | `int` | 受 `MaxStacks` 限制。 |
| `FailureReasonKey` | `StringName` | 供编辑预览与 HUD 说明。 |

## 5. 激活、失效与结算顺序

### 重算触发点

以下事件只标记 `formationDirty`；在当前物理帧结束时统一重算一次，避免交换两艘船时短暂重复触发：舰船生成、确认换位、舰船被击毁、强制位移结束、格位开放/锁定、临时效果到期。

### 重算算法

1. 建立已部署舰船与有效槽位映射，验证虚拟锚点、中心/第一环连接与第二环连通。
2. 应用格位效果，生成相邻边集合。
3. 先检查具名三舰羁绊，再检查具名二舰羁绊，最后检查标签协同。
4. 对每条候选按成员、存活、格位、边关系、冷却、上限依次判定并写入状态。
5. 若候选超过羁绊上限，按 `Priority` 降序、`BondId` 升序保留；其余标记 `Capped`。
6. 汇总效果：同类“伤害放大”只取最高值；护盾、冷却、弹射等按 `combat_rules.md` 的对应上限 Clamp。
7. 发送一次 `FormationChanged` 事件，HUD 和舰队编辑页读取快照更新，不允许各自重新计算。

### 失效与余温

- 默认无宽限：成员被击毁、脱离所需格位或相邻边断开时立即熄灭。
- `FLT_014`“羁绊余温”是唯一例外：已经激活的羁绊可保留 2 秒，期间不再产生新的触发次数；时间结束后重新判定。
- 成员重新满足条件时自动激活；触发型羁绊不重置其 `RemainingCooldown`，防止反复换位刷触发。
- 同一舰船可参与多条羁绊，但每条羁绊各自占一个激活名额。

## 6. 具名舰船羁绊数据

所有成员必须已部署、未处于 `Suppressed` 状态；所有伤害均受单发伤害、弹射与护盾硬上限约束。

| ID | 羁绊 | 成员与条件 | 效果数据 | 反制 / 代价 |
| --- | --- | --- | --- | --- |
| `BND_PAI_001` | 日冕引爆 | 日冕 `ART_001` 与潮汐 `CTL_001` 相邻。 | 潮汐牵引区内的敌人首次受日冕命中时爆炸：日冕主炮 60%，2 层燃烧；同一敌群 CD 1.5 秒。 | 分散敌群、击退潮汐或击杀任一成员可断开。 |
| `BND_PAI_002` | 生命壁垒 | 壁垒 `GRD_001` 与芽舱 `SUP_001` 相邻，至少一艘在前侧。 | 壁垒或芽舱受到一次命中后，芽舱在 0.5 秒后为护盾最低的相邻已部署舰授予 1 层护盾；每 4 秒一次。 | 不恢复被击毁舰船；受单舰护盾 5 层上限限制。 |
| `BND_PAI_003` | 蜂群回路 | 巢母 `CAR_001` 与磁暴 `CTL_002` 相邻。 | 无人机命中瘫痪目标时额外弹射 1 次，伤害 45%，每架无人机 CD 0.8 秒。 | 击杀磁暴或让目标免疫控制会降低收益。 |

| `BND_PAI_005` | 折光回响 | 奇点 `FLG_001` 与折光 `SUP_002` 相邻。 | 奇点每第 3 次主炮命中后，折光为奇点授予 1 层个人护盾；CD 6 秒。 | 只作用这对相邻成员；护盾层不溢出。 |
| `BND_TRI_001` | 引力日冕 | 奇点、日冕、潮汐形成两条相邻边：奇点分别相邻日冕与潮汐。 | 潮汐牵引区中的敌人被日冕引爆后，会被拉向爆点 80 px；每区 CD 3 秒。 | 只由两条相邻成员边触发，不叠加 `BND_PAI_001` 的爆炸伤害。 |
| `BND_TRI_002` | 电磁苗圃 | 芽舱、巢母、磁暴；芽舱需相邻巢母，巢母需相邻磁暴。 | 磁暴瘫痪目标时，巢母无人机获得 20% 移速 3 秒；芽舱每 6 秒为巢母授予 1 层护盾。 | 需要两条边，牺牲紧凑前排。 |
| `BND_TRI_003` | 动能棱堡 | 壁垒、铁幕、破阵均在前侧，且壁垒分别相邻铁幕或破阵之一。 | 前侧首次出现精英时，三者各得 1 层护盾；精英存活期间三者近距武器伤害 +20%。每个精英一次。 | 只保护前侧成员。 |

所有羁绊只由相邻舰船之间的边产生；三舰羁绊必须由两条或三条相邻边组成，不能跨越空格、按全舰队成员数触发，或把效果传递给非相邻舰。`BND_TRI` 与对应 `BND_PAI` 可以同时激活，但不能重复施加同名伤害乘区。

## 7. 标签协同与位置羁绊

标签协同不是具名舰船羁绊。它只检查已部署舰的 `TagIds`，用于给多种构筑提供低强度通用方向；同标签的同级协同不重复激活。

| ID | 条件 | 效果 | 上限 |
| --- | --- | --- | --- |
| `BND_TAG_001` 量子回响 | 2 艘量子舰相邻。 | 任一成员每第三次主炮命中后，相邻舰获得 0.5 秒抗击退。 | 每 4 秒一次。 |
| `BND_TAG_002` 动能阵线 | 2 艘动能舰位于前侧且相邻。 | 首次命中精英时施加 10% 易伤 3 秒。 | 同精英每 6 秒一次。 |
| `BND_TAG_003` 控制链路 | 2 艘控制舰相邻。 | 同一目标连续受到两种控制时，第二种持续时间 +25%。 | 不超过控制 3 秒硬上限。 |
| `BND_TAG_004` 后勤网络 | 2 艘支援舰相邻。 | 每 8 秒为护盾最低的相邻舰授予 1 层护盾。 | 单舰/舰队护盾上限照常生效。 |

## 8. UI、可读性与验收

### 编辑页与 HUD 数据

| 区域 | 必须显示 |
| --- | --- |
| 编队格 | 槽位职责带、是否开放、占用舰、可交换目标、连通高亮。 |
| 舰船卡 | 船名、标签、当前格位、相邻舰、可参与羁绊、是否已部署。 |
| 羁绊面板 | `Active / MissingMember / InvalidPosition / Suppressed / Capped`、成员图标、条件、效果、CD。 |
| 确认预览 | 新激活绿色、将失效红色、数值变化、达到上限、无效原因。 |
| 战斗 HUD | 只显示激活羁绊图标、数量和即将结束的余温；完整条件放入暂停舰队页。 |

### 验收清单

- 19 个槽位坐标唯一，所有相邻关系对称，第二环不能绕过第一环部署。
- 任意交换只触发一次编队重算；不会产生一帧双护盾、双弹射或错误羁绊动画。
- 成员被击毁、被强制位移或重构后，羁绊状态与 UI 在同一帧一致。
- 生命壁垒、折光指挥等所有防御羁绊只产生护盾或控制，不引入生命、护甲或修复。
- 同时激活 7 条候选羁绊时，优先级规则稳定且 UI 明确指出被上限抑制的条目。
- 新增舰船时必须补充：`ShipId`、标签、推荐格位、可参与羁绊、解锁来源、UI 文本和至少一种敌方反制场景。
